# Repository Creation Specification: “AetherForge”

## Project Concept
A hybrid voxel-builder/survival game in the spirit of Minecraft (procedural world generation, infinite terrain, creative building with blocks, exploration, crafting, survival elements) fused with deep factory automation inspired by Factorio and Satisfactory.

### Core pillars
- Voxel world — editable terrain, mining, building with millions of blocks.
- Factory automation — conveyor belts, inserters, assemblers, smelters, fluid pipes, logistics networks, power grids, research trees.
- Kits & modularity — Starter Automation Kits, Mega-Factory Blueprints, Building Expansion Kits, and a planned modding system (asset bundles or ScriptableObject-based kits that players can share).

**Framework:** Unity (recommended: Unity 6 or 2022.3 LTS for DOTS/Burst/Entity performance with thousands of simultaneous factory entities).

---

## 1. Repository Initialization & Hosting (GitHub)

### Create the repository
- Name: `aetherforge` (or your project slug).
- Description: “Voxel builder meets factory automation — Minecraft creativity + Factorio logistics.”
- Public (recommended for community/modding) or Private initially.
- Add a README and `.gitignore` (official Unity template).
- Add a license later (MIT or custom).

### Local setup
1. Clone using GitHub Desktop or `git clone`.
2. Create a new Unity project outside the repo folder first (or move an existing one).
3. Move the Unity project into repo root (`.git` beside `Assets/`, `ProjectSettings/`, etc.).
4. Commit: `chore: initial Unity project skeleton + repo structure`.
5. Push.

Why this order: prevents committing `Library/`, `Temp/`, `Obj/`, and `Builds/`.

## 2. `.gitignore` & Large File Strategy

Use official Unity ignores:

```gitignore
# Unity
/[Ll]ibrary/
/[Tt]emp/
/[Oo]bj/
/[Bb]uild/
/[Bb]uilds/
/[Ll]ogs/
/[Mm]emoryCaptures/
/[Rr]ecordings/
/[Uu]serSettings/

# Asset meta files (only ignore when asset is also ignored)
/Assets/_AetherForge/World/Generated/**/*.meta
/Assets/_AetherForge/Factory/Simulations/Cache/**/*.meta

# Autogenerated
/[Aa]ssets/AssetStoreTools*
/[Aa]ssets/Plugins/Editor/JetBrains*
```

Additions for this project:

```gitignore
# Voxel-specific generated data
Assets/_AetherForge/World/Generated/
Assets/_AetherForge/Factory/Simulations/Cache/

# Build artifacts
dist/
webgl-build/
```

Track large binary assets in `.gitattributes` via Git LFS (for example: `*.fbx`, `*.png`, `*.wav`, `*.asset` and other heavy art/audio formats).

### Git LFS setup (mandatory)
```bash
git lfs install
git lfs track "*.fbx" "*.png" "*.wav" "*.asset"
git add .gitattributes
```

## 4. Automated Builds — GitHub Actions with GameCI

Create `.github/workflows/main.yml`:

```yaml
name: Build & Test AetherForge

on:
  push:
    branches: [ main, develop ]
    paths:
      - 'Assets/**'
      - 'Packages/**'
      - 'ProjectSettings/**'
  pull_request:
    branches: [ main ]

jobs:
  test:
    name: Run Tests
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: game-ci/unity-test-runner@v4
        with:
          unityVersion: 6000.0.0f1
          testMode: all
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}

  build:
    name: Build for ${{ matrix.targetPlatform }}
    runs-on: ubuntu-latest
    needs: test
    strategy:
      matrix:
        targetPlatform: [StandaloneWindows64, WebGL]
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true
      - uses: game-ci/unity-builder@v4
        with:
          unityVersion: 6000.0.0f1
          targetPlatform: ${{ matrix.targetPlatform }}
          buildName: AetherForge-${{ matrix.targetPlatform }}
          customParameters: -detailedBuildReport
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}

      - name: Upload Build Artifact
        uses: actions/upload-artifact@v4
        with:
          name: AetherForge-${{ matrix.targetPlatform }}
          path: build/${{ matrix.targetPlatform }}/
```

### Secrets setup
Repository → Settings → Secrets and variables → Actions:
- `UNITY_LICENSE` = content of generated Unity `.ulf` license file.

### Caching recommendation
Use `actions/cache` for `Library/` keyed by `ProjectSettings/ProjectVersion.txt` + `Packages/manifest.json`.

## 5. WebGL Hosting on GitHub Pages (Prototype)

WebGL is suitable for small demo scenes. Full-scale voxel/factory builds are typically too large.

Optional deployment job:

```yaml
deploy-webgl:
  if: github.ref == 'refs/heads/main'
  runs-on: ubuntu-latest
  needs: build
  steps:
    - uses: actions/download-artifact@v4
      with:
        name: AetherForge-WebGL
        path: webgl-build
    - name: Deploy to GitHub Pages
      uses: peaceiris/actions-gh-pages@v4
      with:
        github_token: ${{ secrets.GITHUB_TOKEN }}
        publish_dir: webgl-build
```

## 7. Edge Cases & Risk Mitigation
- Massive voxel saves → chunk compression + binary serialization.
- Thousands of factory entities → DOTS/ECS + Burst + profiling.
- WebGL memory limits → streaming, LODs, reduced browser simulation fidelity.
- Scene merge conflicts → prefer prefabs + additive loading over direct scene editing.
- Unity version drift → pin versions in workflow and tooling.
- Paid packages → document license usage.
- Modding/kit sharing → clean ScriptableObject + JSON export model.
